# Схема рецепта

Каждый рецепт хранится в `recipes/<id>.md`. Значение `id` должно совпадать с именем файла без расширения и быть уникальным ASCII slug в нижнем регистре: латинские буквы, цифры и дефисы.

## Обязательный frontmatter

```yaml
---
id: apple-charlotte
title: Яблочная шарлотка
servings: 8
time:
  prep_minutes: 20
  cook_minutes: 40
  total_minutes: 60
difficulty: 2
categories:
  - dessert
  - baking
ingredients:
  - id: apple
    name: Яблоко
    amount: 500
    unit: g
---
```

Правила обязательных полей:

- `title` — непустое название блюда.
- `servings` — положительное число порций или единиц выхода. Если исходник не позволяет надёжно определить выход, его нужно уточнить у пользователя.
- `time.prep_minutes` — время подготовки ингредиентов.
- `time.cook_minutes` — время тепловой или основной обработки.
- `time.total_minutes` — полное прошедшее время с ожиданием; оно не меньше каждого из двух остальных значений.
- `difficulty` — целое число от 1 до 5.
- `categories` — непустой список идентификаторов из `categories.yaml`.
- `ingredients` — непустой список ингредиентов. Для каждого обязательны `id`, `name`, `amount`, `unit`.

`amount` — положительное число. Только для ингредиента «по вкусу» допускается `amount: null` вместе с `unit: to-taste`. Дроби записываются десятичными числами, например `0.5`, а не строками `1/2`.

## Необязательный frontmatter

```yaml
cuisine:
  - russian
tags:
  - quick
  - one-pot
equipment:
  - oven
allergens:
  - egg
source: https://example.com/recipe
```

Эти поля добавляются, когда сведения присутствуют в источнике или уверенно следуют из состава и способа приготовления. Значения `tags` должны существовать в `reference/tags.yaml`. Отсутствие необязательного поля не требует вопроса пользователю. `source` может быть URL или кратким текстовым указанием авторства.

## Текст рецепта

После frontmatter обязательна секция `## Приготовление` с последовательным нумерованным списком действий. Секция `## Примечания` необязательна.

## Шкала сложности

1. Элементарно: одна базовая техника, минимальный контроль, трудно испортить.
2. Просто: несколько обычных операций без высокой точности.
3. Средне: важны последовательность, температура или параллельные операции.
4. Сложно: много этапов, специальная техника или точный тайминг.
5. Продвинуто: профессиональные навыки, высокая точность либо несколько сложных компонентов.

Длительность сама по себе не повышает сложность.

## Канонические ингредиенты

Каждый `ingredients[].id` должен существовать в `reference/ingredients.yaml`. Запись имеет форму:

```yaml
- id: apple
  name: Яблоко
  aliases:
    - яблоки
    - яблоко зелёное
  department: produce
```

Перед созданием нового идентификатора нужно проверить существующие `id`, `name` и `aliases`. Синонимы одного продукта используют общий идентификатор; действительно разные продукты, влияющие на выбор или закупку, получают разные идентификаторы.

## Блюда без рецепта

Если пользователь явно разрешил сохранить только название блюда без состава и инструкции, не создавай неполный файл в `recipes/`. Добавь запись в `catalog/dishes.yaml`:

```yaml
- id: pea-soup
  title: Гороховый суп
  status: idea
  categories:
    - soup
  note: Рецепт и ингредиенты пока не заполнены.
```

Обязательны уникальные `id`, `title`, значение `status: idea` и хотя бы одна категория из справочника. `note`, `variants` и `possible_duplicate_of` необязательны. Такая запись означает известное блюдо, но не подтверждает наличие рецепта, ингредиентов, времени или возможности составить закупку.
