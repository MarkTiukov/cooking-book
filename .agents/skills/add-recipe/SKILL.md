# Добавление рецепта

Добавляй переданное пользователем блюдо в базу, сохраняя исходный смысл и не выдумывая критичные сведения. Полный рецепт хранится в `recipes/*.md`; явно разрешённое неполное блюдо — в `catalog/dishes.yaml` со статусом `idea`.

## Подготовка

Перед разбором прочитай корневой `AGENTS.md`, `reference/recipe-schema.md`, `reference/categories.yaml`, `reference/tags.yaml`, `reference/units.yaml`, `reference/ingredients.yaml` и `catalog/dishes.yaml`. Просканируй все `recipes/*.md`, чтобы найти возможный дубликат, переиспользовать канонические ингредиенты и соблюдать сложившиеся названия.

## Разбор входных данных

Извлеки всё, что явно указано, и заполни поля, которые можно уверенно вывести:

- создай уникальный ASCII `id` из названия без вопроса пользователю;
- выбери категории из справочника по назначению и составу блюда;
- оцени `difficulty` по шкале из схемы;
- вычисли компоненты времени, только если исходные интервалы позволяют сделать это однозначно;
- преобразуй обычные дроби в десятичные числа и нормализуй единицы по справочнику;
- преврати описание приготовления в ясные нумерованные шаги, не добавляя неподтверждённых техник, температур или длительностей;
- добавь необязательные `cuisine`, `tags`, `equipment`, `allergens` и `source`, только когда они указаны или уверенно следуют из рецепта; используй только канонические идентификаторы из `reference/tags.yaml`.

Не угадывай число порций по объёму ингредиентов. Не придумывай количество ключевого ингредиента, температуру либо продолжительность приготовления. Для соли, специй, масла для смазывания и похожих второстепенных ингредиентов без точной дозировки допустимы `amount: null` и `unit: to-taste`, если это не меняет сущность блюда.

## Уточнения

После первичного разбора определи, можно ли заполнить все обязательные поля схемы и получить воспроизводимый способ приготовления. Если нет, до любых изменений задай пользователю один компактный набор вопросов обо всех недостающих или противоречивых сведениях. Не спрашивай:

- `id`, категории, сложность или отдел магазина, если их можно уверенно определить;
- необязательные метаданные;
- подтверждение уже явно переданных данных.

Продолжай разбор с учётом ответа. Если обязательная неоднозначность осталась, уточни только её.

Если найден вероятный дубликат, покажи совпадение и спроси, нужно ли отменить добавление, заменить существующий рецепт или сохранить отдельный вариант. Не перезаписывай существующий файл без явного выбора пользователя.

## Блюдо-идея

Создавай запись со статусом `idea` только когда пользователь явно разрешает сохранить блюдо без рецепта или просит перенести список названий. В этом режиме не спрашивай ингредиенты, порции, время и шаги. Выведи `id`, название и категории, сохрани полезную исходную пометку и варианты. Не создавай файл в `recipes/` и не представляй идею как готовый рецепт.

## Сохранение

Когда обязательные данные полны, запрос пользователя на добавление уже считается разрешением создать рецепт; отдельное финальное подтверждение не требуется.

1. Переиспользуй существующий `ingredients[].id`, если название или alias обозначает тот же закупочный продукт.
2. Для нового продукта добавь каноническую запись в `reference/ingredients.yaml`: `id`, русское `name`, полезные встретившиеся `aliases` и `department`. Не создавай разные записи только из-за формы слова или способа нарезки.
3. Создай ровно один файл `recipes/<id>.md` по схеме. Не создавай поддиректории.
4. Если в `catalog/dishes.yaml` есть соответствующая идея, удали её после создания полного рецепта.
5. Запусти `python3 scripts/validate_recipes.py`. Исправь структурные ошибки самостоятельно; семантические противоречия уточни у пользователя.
6. Сообщи путь сохранённого рецепта, основные самостоятельно выведенные поля и результат проверки.

Не изменяй другие рецепты в рамках обычного добавления, кроме явно согласованной замены дубликата.
